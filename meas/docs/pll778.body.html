02 / The trim

Sixteen codes, monotonic, evenly spaced

ui_in[7:4] selects one of 16 discrete VCO settings, there to pull the oscillator back on target across process corners. A trim is only useful if it is monotonic — a code inversion means a control loop can walk the wrong way — so that is the first thing worth measuring, and it is clean here.

03 / Step uniformity

How even the steps are

Borrowing the vocabulary of data converters, because it is the right one: DNL is how much each individual step differs from the average step, and INL is how far the whole curve bends away from a straight line. Both in units of one step.

05 / What is not here

The limits of this measurement

This deck covers the trim and the output noise. It says nothing about the PLL as a loop, and that absence is deliberate.

Lock, loop bandwidth, the divider

Not reported. We did not find a configuration that brought the loop into lock, and ui_in[3:0] — the integer divider select — did not visibly move the output in our setup. A configuration we could not find is a fact about us, not about the silicon, so there is no measurement here to publish either way. The author will know the sequence; we did not.

Above 20 kHz

The two timebases part company above about 20 kHz, where the slower one flattens against its own 8 ns quantisation while the faster keeps falling. That is an instrument floor rather than the oscillator, so the shaded band stops there and the faster capture is the one to read beyond it.

On attribution. The design is —'s. The measurement, and any error in it, is ours. The reference here must be 20 MHz — our first attempt ran it at 10 and produced numbers that meant nothing, which is worth saying because it would have been easy to publish them.
